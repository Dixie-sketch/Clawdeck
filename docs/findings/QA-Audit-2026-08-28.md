## The security issue — SEC-a / CRB-a (HIGH; reproduced ×2; MITIGATED)
`companion/crabd.py` `_is_web_origin` deliberately allows `Origin: null` because the real
QtWebEngine widget presents an opaque `null` origin — but a sandboxed `allow-scripts` iframe on any
visited web page ALSO serializes `Origin: null`. So a visited page can `GET /v1/state` (harvesting
the live sessionId + `pendingPermission.tool`) and `POST /v1/action decide:allow`, approving a real
pending permission the operator never tapped. **Both the security lane and the crabd lane reproduced
the full chain** (a cross-origin caller approved a pending `Bash` command). Escalation-of-existing-
intent, not arbitrary RCE — a page can only approve what a Claude session already proposed while a
prompt is pending, and cannot choose the command.

- **This was the documented reason panel approvals ship OFF by default.** Joe enabled them today
  after the live verification, which made the residual live rather than theoretical.
- **The in-code mitigation rationale is INACCURATE and must be corrected:** the `_is_web_origin`
  docstring claims forged-null stays "bounded by the queue whitelist and the never-auto-allow
  permission broker." True for `queue-continue` (whitelisted); FALSE for `decide` (not whitelisted;
  the broker keys pending permissions by sessionId alone, and sessionId is disclosed by the same
  null-readable `/v1/state`). No second barrier.
- **Mitigation applied 2026-08-28:** `panelApprovals.enabled` set to `false` on the live host
  (was `true`). Exposure closed — no armed path to hit. Reversible in one tap / one word.
- **The real fix is operator + glass gated.** Legitimate widget and attacker are indistinguishable
  by origin. Options: (1) leave approvals off (original posture, safest); (2) allowlist the widget's
  ACTUAL origin — needs measuring what QtWebEngine sends AND whether the widget needs ACAO to read
  `/v1/state` (dropping ACAO:null on the READ path defangs the attack by denying the attacker the
  sessionId, IF the real widget doesn't rely on CORS to read state); (3) a heavier auth scheme.
  **Enabler shipped this wave:** crabd now records distinct `Origin` values seen, so the widget's
  true origin can be read remotely from its live polling — turning the blocking glass measurement
  into a passive read. Decision + re-enable stays Joe's.

## audit-0424 findings — ALL FIXED in crabd 0.26.0 (second fix pass)
The seventh lane's 12 findings (`audit-0424-crabd.md`) were fixed after the six-lane wave, each
with a failing-pre-fix test (11 mutation-confirmed; A-09 a comment correction). Suite 1026→1038.
- **A-01 / A-02 (P1, dormant while approvals off):** `_await_permission` skips `clear_permission`
  while `broker.has_pending()` — a replaced hold no longer stands down the live hold's card
  (orchestrator-reproduced fix); a Notification on a needs_input row always transfers
  `permission_alert` ownership, making the behavior hook-order-INDEPENDENT. **Both now safe to
  re-enable approvals against.**
- **A-03 (P2, live):** `UserConfig._write` is now temp+`os.replace` atomic — a failed write can't
  empty config.json (the crabd-runtime sibling of setup's SET-a2).
- **A-04 (P2, live):** `GitLookup.get` bounds the fs walk to `GIT_READ_BUDGET_SEC=1.0` on a worker
  — an unreachable network cwd can't stall the build past ~1s (was 21s).
- **A-05 (P2, live):** needs_input rows keep their exemption but gain a 36h age ceiling + 512 LRU
  cap (oldest-by-`at` first; recent waiting rows never dropped).
- **A-06:** GitLookup cache bounded LRU (256). **A-07/A-08:** sub-quantum + idle>total CPU windows
  serve null, not fabricated 0.0. **A-09:** false "no-op" comment corrected. **A-10:** stand-down
  now writes a ring event (A-01/A-02-class issues leave a trace). **A-11:** untimestamped usage
  record skipped, not dated `now`. **A-12:** `note_activity` clamps the written `since`/`at` to now.
